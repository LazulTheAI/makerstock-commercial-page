Cette partie documente le fonctionnement interne des six mécaniques clés de MakerStock : ce qui se passe sous le capot quand vous exécutez un run, quand vous réceptionnez une livraison, ou quand une vente est enregistrée dans BigCommerce.

Point critique 4.1

Le cycle de vie d'un run de production

Un run est l'unité atomique de production dans MakerStock. Il représente l'exécution d'un nombre défini de batches d'une recette donnée. Comprendre son cycle de vie est essentiel pour piloter la production correctement.

Les quatre statuts
Planifié
En file d'attente, stock non déduit
→
En cours
Démarré par un opérateur
→
Terminé
Stock déduit, COGS calculé
↘
Annulé
Irréversible, pas de restitution
📋
Planifié → mise en file d'attente sans déduction de stock
Quand un run est planifié (depuis desktop ou mobile), il est enregistré mais le stock n'est pas encore touché. Si le stock est insuffisant au moment de la planification, MakerStock le signale mais laisse passer le run en file — une alerte prévisionnelle est générée. Un run planifié peut être annulé sans conséquence sur le stock.
⚙️
Planifié → En cours : démarrage par l'opérateur
Un opérateur (depuis le mobile, onglet Fabrication) ou un admin (depuis le desktop) appuie sur "Démarrer". Le statut passe à EN_COURS. À ce moment, MakerStock vérifie à nouveau la disponibilité du stock. Le run est visible en temps réel sur le desktop.
✅
En cours → Terminé : déduction, crédit stock, COGS
À la terminaison, trois actions atomiques sont déclenchées simultanément : (1) les matières premières sont déduites du stock selon la méthode FIFO, lot par lot, avec enregistrement de la traçabilité ; (2) le stock de produits finis est crédité du nombre d'unités produites ; (3) le COGS réel du run est calculé à partir des coûts unitaires des lots consommés. Ces trois opérations sont réversibles uniquement via un ajustement manuel ultérieur.
Traçabilité lots — Pro+
⚠️
Run terminé avec stock insuffisant
Si le stock d'une ou plusieurs matières est insuffisant au moment de l'exécution, MakerStock l'indique dans le détail du run (onglet "Manques") mais laisse le run se terminer. Le stock descend à zéro pour les matières concernées — il ne devient pas négatif. Une alerte de rupture est générée.
Alerte de rupture
🚫
Annulation — irréversible, aucune restitution automatique
Un run en statut PLANIFIE ou EN_COURS peut être annulé. L'annulation est définitive. Si le run était EN_COURS et que des matières avaient déjà été physiquement consommées, le stock ne sera pas restitué automatiquement — une correction manuelle via ajustement de stock est nécessaire.
Irréversible
Depuis desktop
Planifier, lancer directement, voir le détail, exporter le CSV de traçabilité, annuler.
Depuis mobile
Planifier, démarrer un run planifié, terminer un run en cours. Pas d'accès au détail financier.
Export CSV traçabilité
Disponible après terminaison : matière, lot, quantité consommée, DLC, fournisseur, coût. Format compatible comptabilité.
Lancer sans planifier
Possible depuis le desktop uniquement. Le run passe directement de "nouveau" à TERMINE si le stock est suffisant, sans étape intermédiaire.
Point critique 4.2

Gestion du stock matières — lots, FIFO et mouvements

Le stock de matières premières est géré lot par lot. Chaque entrée en stock crée un lot distinct avec son propre coût unitaire, numéro de lot et DLC. La consommation suit la règle FIFO (premier entré, premier sorti).

Fonctionnement du FIFO illustré
Exemple — Farine de blé · 3 lots en stock · Run de production consommant 8 kg
Avant run
LOT-A · 12/03/2025
DLC 31/08/2025 · 1,20 €/kg
3 kg
LOT-B · 28/03/2025
DLC 28/02/2026 · 1,15 €/kg
7 kg
LOT-C · 10/04/2025
DLC 30/06/2026 · 1,18 €/kg
10 kg
Après run
(8 kg déduits)
LOT-A · épuisé
3 kg consommés en totalité
0 kg
LOT-B · partiel
5 kg consommés sur 7
2 kg
LOT-C · intact
Non touché
10 kg
COGS matière = (3 kg × 1,20 €) + (5 kg × 1,15 €) = 3,60 € + 5,75 € = 9,35 €
📥
Entrée en stock — création d'un lot
Chaque entrée de stock (manuelle, réception fournisseur ou import) crée un nouveau lot horodaté avec : quantité, coût unitaire au moment de l'entrée (snapshot), numéro de lot optionnel, DLC optionnelle. Si le matériau est configuré avec "DLC obligatoire", la date d'expiration est requise à chaque entrée.
⚡
Ajustement de stock — pas de création de lot
Un ajustement (+ ou −) modifie directement le lot sélectionné ou le lot le plus ancien (FIFO). L'ajustement nécessite une raison obligatoire (inventaire physique, perte, casse, correction…). Le mouvement est tracé dans l'historique avec le type AJUSTEMENT.
⚠️
Dégrèvement de lot — retrait ciblé
Depuis la vue des lots d'un matériau, il est possible de "dégrever" un lot spécifique (perte, casse, contrôle qualité) en indiquant la quantité et une raison. Le dégrèvement cible précisément ce lot, indépendamment de l'ordre FIFO. Cette opération est irréversible.
Irréversible
🔁
Transfert inter-entrepôts
Disponible depuis le desktop uniquement (plan Business). Un lot peut être transféré d'un entrepôt source vers un entrepôt destination. Le lot conserve son numéro, sa DLC et son coût unitaire d'origine. Le stock de l'entrepôt source diminue, celui de la destination augmente.
Business
📊
Valorisation du stock
La valeur totale du stock d'un matériau est calculée en temps réel : somme des (quantité restante × coût unitaire) pour chaque lot actif. Cette valeur est visible dans la colonne "Valeur stock" du tableau des matières et utilisée dans le rapport financier.
⚠️
Le coût unitaire d'une matière ≠ le coût d'un lot Le champ "coût unitaire" dans la fiche d'une matière première est le coût de référence par défaut. Chaque lot a son propre coût unitaire, enregistré au moment de l'entrée en stock (snapshot). C'est le coût du lot — pas le coût de référence — qui est utilisé dans le calcul du COGS lors d'un run.
Point critique 4.3

Cycle d'approvisionnement fournisseur

Les bons de commande fournisseurs permettent de tracer le cycle complet d'une commande matières : de la création en bureau à la réception physique en atelier. Ce module est disponible à partir du plan Pro.

Les cinq statuts d'un bon de commande
Brouillon
Créé, non envoyé
→
Envoyé
Transmis au fournisseur
→
Part. reçu
Réception partielle
→
Reçu
Toutes lignes reçues
↘
Annulé
Depuis Brouillon ou Envoyé
📝
Création du bon (Brouillon) — desktop uniquement
L'admin crée un bon de commande en sélectionnant un fournisseur, en ajoutant des lignes (matériau, quantité, prix unitaire), et en renseignant une date de livraison prévue. Le bon en statut Brouillon peut être modifié et supprimé librement.
Pro+
📤
Envoi au fournisseur — passage en statut Envoyé
En cliquant "Marquer comme envoyé", le bon bascule en ENVOYE. Il n'est plus modifiable. Il devient visible dans l'onglet "Approvisionnements" du mobile, pour que les opérateurs puissent le réceptionner à la livraison. En retard si la date de livraison prévue est dépassée.
📦
Réception — mise à jour du stock par ligne
Depuis le mobile (ou le desktop), l'opérateur saisit pour chaque ligne : la quantité effectivement reçue, le numéro de lot fournisseur (optionnel), la DLC (obligatoire si le matériau l'exige) et l'entrepôt de destination. La quantité est immédiatement créditée en stock à la validation. Si toutes les lignes ne sont pas complètement reçues, le bon passe en PARTIELLEMENT_RECU.
Traçabilité lots — Pro+
🔄
Réceptions partielles successives
Un bon peut être réceptionné en plusieurs fois. À chaque réception partielle, le stock est crédité de la quantité saisie. La progression de réception est visible en pourcentage par ligne. Le bon passe en RECU uniquement quand toutes les lignes ont atteint leur quantité commandée.
💡
Sur-réception possible Il est possible de réceptionner plus que la quantité commandée sur une ligne (livraison excédentaire). MakerStock l'indique visuellement mais l'autorise. Le stock est crédité de la quantité réellement saisie.
Point critique 4.4

Système d'alertes — types et déclencheurs

Le tableau de bord Alertes est la page d'accueil de MakerStock. Il affiche en temps réel les situations nécessitant une attention, regroupées par niveau d'urgence. Les alertes sont rafraîchies automatiquement toutes les 30 secondes.

🔴
Stock bas — matière première
Le stock total d'une matière première est descendu sous le seuil d'alerte configuré dans la fiche matériau.
Déclencheur : stock total < seuil d'alerte
🟡
Alerte prévisionnelle — run à risque
Un run planifié ne pourra pas être exécuté faute de stock suffisant au moment où il est prévu. Affiché dans le bandeau "Prévisionnelles".
Déclencheur : stock insuffisant pour un run planifié
🔵
Stock bas — produit fini
Le stock total d'un produit fini est descendu sous le seuil d'alerte configuré dans la fiche produit.
Déclencheur : stock produit < seuil d'alerte
⚫
Rupture produit / Annulation
Rupture totale (stock = 0) ou annulation d'une commande fournisseur impactant un approvisionnement attendu.
Déclencheur : stock = 0 ou annulation de commande
🔔
Acquittement d'une alerte
Toute alerte peut être acquittée manuellement depuis le desktop (bouton "Acquitter"). L'alerte acquittée est archivée et disparaît des alertes actives. Elle reste visible dans l'historique des 30 derniers jours. Une alerte acquittée peut réapparaître si la condition qui la déclenchait n'est toujours pas résolue (par exemple, le stock est toujours bas).
📊
Bandeau d'alerte en haut du mobile
L'interface mobile affiche un bandeau rouge persistant en haut de chaque écran quand il existe au moins une alerte de stock bas non acquittée. Ce bandeau est visible depuis tous les onglets, pas seulement depuis le dashboard. Il disparaît dès que toutes les alertes urgentes sont résolues ou acquittées.
🔄
Rafraîchissement automatique — 30 secondes
Le tableau de bord Alertes se rafraîchit automatiquement toutes les 30 secondes sans rechargement de page. Le dashboard mobile se rafraîchit toutes les 60 secondes. Un bouton "Actualiser" permet un rafraîchissement manuel immédiat depuis le desktop.
Point critique 4.5

Calcul du COGS — méthode et composantes

Le COGS (Cost of Goods Sold — coût de revient) est calculé automatiquement à chaque run terminé. Sa précision dépend du plan souscrit : le plan Starter ne couvre que les matières premières, le plan Pro ajoute la main-d'œuvre et les charges, le plan Business permet le rapport P&L complet.

Formule selon le plan
COGS — Starter (matières premières uniquement)
COGS = Σ ( qté_lot × coût_unit_lot ) par lot FIFO consommé
COGS complet — Pro+ (matières + MO + charges variables)
COGS = Σ ( qté_lot × coût_unit_lot ) matières premières FIFO + ( taux_horaire × nb_opérateurs × durée_recette ) coût MO par batch + coût_variable_batch énergie, emballage (saisi sur la recette)
COGS + charges fixes imputées — Business (rapport P&L)
Coût complet / unité = COGS Pro / unités_produites + Σ ( charge_fixe_mensuelle / volume_cible_mensuel ) loyer, amortissement…
💡
Prix de vente recommandé — calcul automatique (Pro+)
À partir du COGS complet, MakerStock peut calculer un prix de vente suggéré. Ce calcul intègre la marge cible définie sur la recette. Le prix recommandé est visible dans la fiche recette et dans la fiche produit. Il n'est pas synchronisé automatiquement dans BigCommerce — il est consultatif.
Pro+
📤
Export comptable XLSX (Pro+)
Disponible depuis Pilotage → Rapports. Exporte sur la période choisie : mouvements de stock, valorisation FIFO, COGS détaillé par run et par produit, récapitulatif des charges. Format structuré, compatible avec les logiciels comptables courants. Méthode des coûts complets, valorisation FIFO, mention légale incluse.
Pro+
📊
Rapport P&L par produit (Business)
Génère un document complet : synthèse exécutive (CA, COGS, marge brute), détail des coûts par produit, structure des charges fixes, calcul du seuil de rentabilité (point mort) et projection CA / marge sur 12 mois. Requiert au minimum un run terminé, un taux horaire et des charges fixes configurés.
Business
Point critique 4.6

Synchronisation BigCommerce

La relation entre MakerStock et BigCommerce est le cœur du système. Elle n'est pas bidirectionnelle sur toutes les données — il est important de comprendre ce qui circule dans quel sens, et ce qui reste indépendant.

BigCommerce
Catalogue produits (nom, SKU, prix)
Commandes clients
Stock BC (géré par BC)
Identité marchand (auth)
↓
vers MS
↑
depuis MS
MakerStock
Stock interne (géré par MS)
Recettes & COGS liés aux SKU
Matières premières consommées
Traçabilité lots & DLC
🔄
Synchronisation du catalogue produits (BC → MS)
MakerStock importe le catalogue produits depuis BigCommerce : nom, SKU, ID produit, ID variante, prix de vente. Cette synchronisation peut être déclenchée manuellement depuis la page Produits & stock. Les produits créés dans BigCommerce après l'installation doivent être synchronisés pour apparaître dans MakerStock.
⚡
Déduction automatique à la vente (BC → MS)
Quand une vente est enregistrée dans BigCommerce pour un produit lié à une recette principale dans MakerStock, la déduction de matières premières est déclenchée automatiquement. MakerStock calcule le nombre de batches consommés (quantité vendue × batches par unité), puis déduit les matières en FIFO. Ce mécanisme fonctionne uniquement si la recette est marquée "principale" sur le produit.
🧮
Deux stocks indépendants — BC stock ≠ MS stock
MakerStock maintient son propre stock de produits finis, indépendant du stock BigCommerce. Le stock BC est le stock disponible à la vente visible sur la boutique. Le stock MS est le stock physique en atelier, issu des runs de production. Ces deux stocks ne sont pas synchronisés automatiquement — c'est une séparation intentionnelle qui permet de gérer des réserves, des lots réservés ou des délais de mise en vente.
Important
🔗
Ratio batches par unité vendue — clé de la liaison
Lors de la liaison recette ↔ produit, l'admin renseigne le ratio "batches par unité vendue". Exemple : si 1 batch produit 12 bougies, et qu'une bougie est vendue à l'unité, le ratio est 1/12 = 0,0833 batch par unité. Ce ratio est utilisé pour calculer la consommation matières à chaque vente. Un ratio mal configuré entraîne une déduction incorrecte.
Configurer avec soin
🚨
Le ratio batches/unité est critique Une erreur dans ce ratio entraîne une déduction de stock incorrecte à chaque vente. Vérifiez-le attentivement lors de la liaison et après tout changement de taille de batch dans une recette. Il est modifiable à tout moment dans la fiche produit, onglet "Recettes liées".
